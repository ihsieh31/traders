## 1. 一句話

找出一條**完全決定式、零 LLM、零券商**的量化公式，輸入美股日線，
輸出**主專案每天要買的 20 支股票的清單**，並且在統計上站得住腳。

---

## 2. 這是什麼 / 這不是什麼

### 是

一個**公式搜尋與驗收的框架**。輸入：歷史日線 OHLCV + 候選公式。
輸出：每條公式在多個持有期上的橫斷面預測力、Top-20 組合的報酬與成本後年化，
以及一條**事先寫死的**通過／不通過判定。

### 不是（scope 邊界，硬性）

- **不是** backtest engine（不模擬部位 sizing、滑價、bracket 保護單、訂單類型）
- **不是** P&L 計算器
- **不是** portfolio optimizer
- **不會** 呼叫任何 LLM
- **不會** 對券商帳戶做任何讀寫
- **不會** 修改 `tradingagents/` 任何一行

**為什麼不做 backtest**：橫斷面 IC 是一個很便宜的守門員。如果公式在實際持有期上
IC ≈ 0，backtest 出來必定是雜訊。反之 IC 顯著才值得投入 backtest 工程。

**範圍膨脹的處置**：若過程中發現需要部位 sizing、成本模型或組合建構才能回答核心問題，
**停下來回報，不要自行擴充**。那代表要重新決策。

### 4.3 資料來源限制（已實測，非推測）

- **歷史深度 10.7 年**（2016-01-04 起）。再往前請求回空。這是資料源限制。
- **SIP 必須用 SIP**，不可 fallback 到 IEX。IEX 的 OHLC 只聚合 IEX 成交，
  量能差 60 倍以上，收盤價也不同。
- **`yfinance` 不可用**。日曆缺口率 22.11%（SIP 為 1.14%），會讓
  `validate_and_clean_bars` 正確地 fail closed，大多數日期的橫斷面歸零。
  程式碼保留 `--source yfinance` 僅為無權限環境備用，**不建議使用**。

### 4.4 必須隨任何結論揭露的限制（即使全部測試通過也成立）

1. **存活者偏差**：宇宙是「**今天**仍 ACTIVE 且 tradable」的美股。已退市、
   已被併購的標的一列都不在資料中。方向**偏樂觀**。占比**無法從本資料集量測**
   （需 CRSP/Compustat 歷史成分股名單）。**不要**宣稱已處理退市偏差。
   **不要**用未驗證方法修正。
2. **無 point-in-time 市值**：本研究的宇宙不是生產宇宙（生產另有 $300M 市值門檻，
   會再砍掉約 70%）。**結果不可直接外推到完整生產管線。**
3. **僅分割調整，未含分紅**。對 20/40/60 日視窗是實質偏誤，方向為高估。
4. **交易成本是估計值**，非實測成交成本。R12 的四個組成項中，
   佣金與交易稅假設為 0，價差與滑價為文獻式估計值。
5. **容量未評估**。R13-L2 的 0.1% 參與率上限只是一個**預警機制**，
   不是容量研究。真正的容量需要用實際 fill 資料推導。
6. **因子挖掘歷史上的失敗率極高**。文獻中絕大多數已發表 alpha 無法複製。
7. **本專案不做部位風控**（R14）。20 檔等權是簡化假設，不是建議的組合建構。
   通過了本專案全部 11 條條件的公式，**仍然不是可部署策略**。
8. **單一 holdout 不足以支撐結論**。一次通過是鼓勵，不是證明。
   R2 的 walk-forward 與 R5 的參數平台要求是補償，不是保證。
9. **regime 分層會消耗樣本**（R15）。切成 4 個 regime 後每個的期間數是
   全體的四分之一，統計效力隨之下降。分層結果的效力必須逐格揭露。

### A. 期間與資料邊界

#### R1 期間切分與 holdout

```
探索期 discovery    2016-01-04 .. 2020-12-31    在此找公式
驗證期 validation   2021-01-04 .. 2025-12-31    完全不參與任何選擇，只驗證
```

**驗證期是消耗品。用掉就沒了。** 因此：

- 公式**只組一次**，用 R3 的規則，不得因驗證結果回頭改組成
- 驗證結果不論好壞，**不得**回頭到探索期重新篩選並重跑
- 若第一輪不達標，正確處置是**如實回報失敗**，不是迭代到通過為止
- **架構上強制**：挖掘階段的執行路徑必須對驗證期不可見（沙箱／斷言），
  不得靠「我記得不要看」（見 `process.md` S-25）

#### R2 Walk-forward（滾動前推驗證）

單一 holdout 只能證明「一次通過」，不能證明「穩健」。因此在**探索期內部**
另做滾動前推驗證：

```
把探索期切成 K >= 4 個連續 fold
每個 fold：前 60% 組公式（用 R3 的規則，不看後 40%），後 40% 驗證
所有 fold 的組成規則必須完全相同 —— 不得逐 fold 調參
```

- 報告**每個 fold** 的結果，與全部 fold 的合併結果
- **至少 3/4 的 fold 與合併結果同號**才算通過
- 每個 fold 的**獨立期間數必須報出**。若 `sessions / horizon / K` 太小，
  該 fold 的結果標示為統計效力不足，不得單獨引用
- walk-forward 在探索期內進行，**不取代** R1 的驗證期。兩者都要做

### B. 公式定義與防過度擬合

#### R3 公式組成

```
1. 逐日橫斷面 Spearman IC（每個日期一個 IC 值）
2. 計算有效獨立檢定數 N_eff 與族校正門檻 t_bonf（R9）
3. 保留通過門檻的成分
4. 對每個成分取「IC 符號 × 當日橫斷面百分位」，使全部指向同一方向
5. 複合分數 = 成分百分位的【等權平均】
6. 每個持有期分別取分數前 20 檔等權
```

**為什麼等權不用 IC 加權**：IC 加權讓少數成分主導，而那些正是探索期最可能
過度擬合的。等權較保守，也較符合「我要的是穩健不是最高 IC」。

**為什麼 Top-20 等權**：主專案每天要 20 個部位，等權是最簡潔的假設，
且與主專案的實際組合建構一致。

#### R4 參數預算與複雜度上限

```
自由參數總數 <= 6      （含持有期在內）
```

每個參數**只能**是以下三種之一：

| 允許 | 例子 | 為什麼安全 |
|---|---|---|
| 視窗長度（整數天數） | 20、60、120 | 離散、可窮舉掃描、數量少 |
| 符號 | +1 / −1 | 只有 2 種可能 |
| 事前寫死的權重集合 | 0.5 / 0.5 | **事前**決定，不依結果調整 |

**禁止**（這三類是過度擬合的主要來源）：

- 連續可優化的係數（回歸係數、風險溢價、Sharpe 最優化）
- 由機器學到的係數
- 依結果調整的門檻（「t > 2.1 比較好，那就用 2.1」）

**每一個參數都必須報出「它被掃過幾個值」**，這個數字要計入 R9 的
多重檢定總數。一個被掃過 7 個值的視窗長度，成本等於 7 次檢定。

#### R5 參數穩健度 — 必須是「平台」不是「尖峰」

對**每個**參數做掃描，並遵守：

1. **整條曲線一起報**，不是只報最好的那一格
2. 通過必須是**平台**：連續 **3 個相鄰值**同號，且量級相近（相鄰格之間
   變化 < 50%）
3. **尖峰 = 過度擬合的直接證據**。只有單一格顯著時，該公式判定不通過，
   理由寫「參數不穩健」
4. 掃描值必須**事前寫定**（例如 `{10, 20, 30, 60, 120}`），
   不得看到曲線後再加密網格
5. 掃描使用**探索期資料**。驗證期只在公式凍結後跑一次

**硬規則** 見 S-31。一條在參數空間裡是尖峰、在數字上是 +15% 年化的公式，
在真實市場上會是雜訊。

### C. 量測紀律

#### R6 進場與出場

```
entry  = open[as_of + 1]              # 下一交易日開盤進場
exit   = close[as_of + 1 + (N-1)]     # 進場後第 N 個交易日收盤出場
forward_return(N) = exit / entry - 1
```

決策在 `as_of` 當日做出，最早只能下一個交易日開盤成交。
**訊號產生與交易執行至少錯開一個完整的交易時點**，這是最低要求，
不是可調參數。

**不可**改用 close-to-close（那是 look-ahead bias）。若要輸出 close-to-close
作為文獻對照，必須與主數字並列且標記為有偏誤。

#### R7 未來函數防護

**這是本專案最貴的一類錯誤**：它不會讓結果變醜，只會讓結果變假。

| # | 規則 |
|---|---|
| L1 | **每一個輸入欄位都必須標註可得時間點**（as-of 時間戳）。做不到的欄位不得使用 |
| L2 | **財報類輸入用實際公布日**（申報日／發布時間），**不是會計期間結束日**。兩者可差 30–90 天 |
| L3 | **盤中資料不得用當日收盤價計算當日訊號**，除非決策時點明確在收盤之後 |
| L4 | **橫斷面母體不得由任何未來資訊決定**——包含市值、可交易狀態、上市狀態、資料完整度 |
| L5 | **回填（backfill）與修訂（revision）必須用當時的版本**。用最新修訂值回填歷史 = look-ahead |
| L6 | **稀疏資料的傳播不得跨越 as_of**。rolling 視窗必須只往回看，且缺失值不得 forward-fill（見 S-23） |
| L7 | **橫斷面百分位的母體與時點必須一致**：同一天所有標的用同一個母體、同一個時點 |

**自我測試必須能抓到 look-ahead**。目前架構下唯一能抓到的是
**prefix invariance**：把面板截短，已回報的因子值不得改變。改變了就是有前視窗。
（見 R17 的 harness 要求）

**⚠️ 一個常見的錯誤安全感**：用「兩邊共用同一個前瞻報酬陣列」的對稱性檢查
去驗證前瞻報酬，是**無效的**——前瞻報酬若錯，錯誤在相減時完全抵消。
目標變數必須有**對寫死期望值**的絕對值檢查。見 `process.md` S-14。

#### R8 統計

- **Newey-West**，lag 以**取樣單位**計：`nw_lag = max(1, ceil(horizon / date_step))`
- **兩套取樣，用途不同，不可混用**：

  | 取樣 | 設定 | 唯一用途 |
  |---|---|---|
  | 重疊取樣 | `date_step = 5` | 因子層 IC 與其推論 |
  | 非重疊取樣 | `date_step = horizon` | Top-20 組合的報酬、換手、成本、年化 |

- 報告用普通 t 值即視為無效（見 `process.md` S-1）
- **非重疊取樣下每側的獨立期間數是 `sessions / horizon`**。60 日持有約只有
  20 個點，**即使通過也必須標示統計效力不足**。

#### R9 多重檢定

```
N_eff  = n² / Σλ²      （λ 為成分 IC 序列相關矩陣的特徵值；對角為 1 故 Σλ = n）
t_bonf = 雙側 α=0.05 的族校正門檻
```

- `N_eff` 必須由**實際通過初步篩選的成分**的相關矩陣估計，不是候選總數
- **真實檢定總數必須回報**，來源包含三處，缺一不可：
  1. 被自己淘汰的變體數（R4）
  2. R5 的參數掃描格數
  3. 曾經考慮過但未落地的方向
- **`t_bonf` 只由探索期推估**，不得用驗證期決定門檻
- **不得**在多個持有期上挑選最好的那個再宣稱——那會把檢定數膨脹到
  `成分數 × 持有期數`，門檻必須同步上升（見 `process.md` S-5）

### D. 可交易性

#### R10 通過條件

全部滿足才算通過。**任何一條不滿足就是不通過**，不通過是有價值的負面結論。

| # | 條件 | 為什麼 |
|---|---|---|
| 1 | 驗證期 Top-20 組合 `\|t_NW\| ≥ t_bonf` | 未參與選擇的資料上仍顯著 |
| 2 | 探索期與驗證期**同號** | 方向一致，不是雜訊 |
| 3 | 驗證期**扣換手成本後年化 > 0** | 可交易 |
| 4 | **成本 2.0x 時驗證期淨年化仍 > 0** | 成本估計不準時還能不能活（見 R12） |
| 5 | **優於主專案現有的選股分數**在同一驗證期的表現 | 新東西必須打贏舊東西 |
| 6 | 在**寬宇宙**與**生產資格宇宙**都成立 | 只在寬宇宙有效等於在生產裡被濾掉 |
| 7 | **至少 3/4 的 walk-forward fold 同號** | 不是單一區間的巧合（見 R2） |
| 8 | **每個參數的 ±1 格仍同號**（R5 平台） | 參數不穩 = 過度擬合 |
| 9 | **至少 2 個市場狀態同號**，且合計 t 達標 | 不是單一 regime 的產物（見 R15） |
| 10 | **剔除最佳 5% 交易後仍同號** | 不是靠少數幾筆（見 R16） |
| 11 | 下單量 ≤ ADV20 的 0.1% | 真的有辦法成交（見 R13） |

#### R11 兩層宇宙

| 層 | 定義 | 用途 |
|---|---|---|
| **寬宇宙** | `price >= 5.0`（無流動性門檻） | 公式搜尋。橫斷面大，統計效力高 |
| **生產資格宇宙** | `price >= 5.0` 且 `ADV20 >= $20,000,000` | 驗證在主專案管線裡是否存活 |

**兩層都必須通過**（R10 條件 6）。只在寬宇宙有 IC 的公式在生產裡會被流動性
門檻整個濾掉，等於沒有價值。

**已知代價（必須揭露）**：`ADV20 >= $20M` 會把「非流動性股票反轉最強」
這個維度**整個截掉**，使其在生產資格宇宙上不可測。這是**不可測**，
不是**被推翻**。見 `process.md` S-24。

**兩層的橫斷面母體定義必須完全一致**，且與主專案的篩選母體一致
（見 `process.md` S-12）。母體不一致造成的差異可以達到 90 分／100。

#### R12 交易成本

**成本必須拆成四個組成項**，不得用單一數字：

```
單邊成本 = 佣金 + 交易稅 + 價差 + 滑價
```

本專案採用的**保守估計（事前寫定，非實測）**：

| 組成 | 單邊 | 說明 |
|---|---:|---|
| 佣金 | 0.000% | 紙上交易假設無佣金 |
| 交易稅 | 0.000% | **不是真的沒有**——州交易稅、賣空借券費、Regulation SHO 費都可能非零。不確定性由 2x 情境吸收 |
| 價差 | 0.020% | |
| 滑價 | 0.030% | 依 R13 的流動性層級調整 |
| **合計** | **0.050%** | 往返 **0.100%** |

**成本敏感度（全部必報，且 2.0x 是硬性條件 R10-4）**：

| 情境 | 往返成本 | 用途 |
|---|---:|---|
| 基準 | 0.100% | 主數字 |
| 1.5x | 0.150% | 敏感度 |
| **2.0x** | **0.200%** | **通過條件。2x 仍不賺 → 不可交易** |

其餘算式：

```
換手率   = 0.5 × Σ|w_new − w_old|      w = 1/20 等權
首次建倉 = 換手率記為 1.0        （見 process.md S-21）
每期淨利 = 毛利 − 換手率 × 往返成本
年化     = 每期平均 × (250 / N)
```

**硬規則** **不得**因為 2x 情境不通過就調低成本假設。成本假設是
事前寫定的；不通過就是不通過（見 `process.md` S-36）。

#### R13 流動性與下單量

| # | 規則 |
|---|---|
| L1 | 最低成交額門檻：生產資格宇宙 `ADV20 >= $20,000,000`（R11 的宇宙定義） |
| L2 | **下單量上限**：單一標的單期下單金額 ≤ `ADV20 × 0.1%`。超出即該期不可交易，必須報出 |
| L3 | **分層滑價**：依 `ADV20` 對 R12 的滑價項乘一個係數 |

| 流動性層 | ADV20 | 滑價係數 |
|---|---|---:|
| 大型 | ≥ $100M | 1.0x |
| 中型 | $20M – $100M | 1.5x |
| 小型 | $5M – $20M | 2.5x |
| 微型 | < $5M | **超出本專案範圍，不測** |

**為什麼 0.1%**：這是「我的單子在市場裡有多小」的度量。若資金規模擴大，
這個係數會先突破——它是**容量上限的早期警訊**，比等到成交失敗才發現好。
（R12 的成本假設已含價差，但 L2 管的是「有沒有量」，兩者不同）

**硬規則** 見 S-37。`ADV20` 門檻同時也會**截掉整個研究維度**
（見 `process.md` S-24）：寬宇宙與生產資格宇宙必須都報，缺一不可。

#### R14 風險管理——邊界與可交接性

**本專案不做**：部位 sizing、停損、最大單日虧損、最大回撤斷路器、
最大槓桿、動態曝險調整。這些是**主專案的事**，做了就是範圍膨脹（R19）。

**但公式必須滿足三個可交接條件**，否則主專案的風控層沒有東西可用：

| # | 條件 | 主專案需要它做什麼 |
|---|---|---|
| H1 | 公式輸出是**「每檔一個分數 + 一個持有期」**，不是單一黑箱數字 | 依分數做 sizing、依分數設權重上限 |
| H2 | **20 檔之間的相關性矩陣必須被報出** | 偵測假分散（見 `process.md` S-39） |
| H3 | **組合的日報酬序列必須被輸出** | 算波動、最大回撤、與主專案 HWM 的關係 |

**必須揭露**：本專案**不回答**「這個公式該下多少錢」。
把一個通過了 IC 與成本檢驗的公式直接當成可部署策略，是誤用。

**本專案的 20 檔等權假設是一個簡化，不是建議**。主專案的真實組合建構
（有曝險上限、有相關性約束、有流動性上限）會讓結果不同於此處的數字。

### E. 穩健性

#### R15 市場狀態分層

**只用 trailing 資料定義狀態**（定義本身不得有 look-ahead）：

```
等權市場報酬 m_t          = 當日全宇宙對數報酬的中位數（nanmedian）
趨勢 regime               = sign( m_t 的 trailing 60 日累積 )        → 牛市 / 熊市
波動 regime               = realized σ 的 trailing 60 日 vs 全期中位數 → 高波動 / 低波動
```

- 報告**每個 regime 分組**的 IC 與 Top-20 組合報酬
- 本資料集涵蓋 2 次熊市（2018Q4、2022）與 1 次崩盤（2020-03），
  足以做分層，但每個 regime 的**期間數必須報出**。少於 20 個非重疊期間的
  regime 標示為樣本不足
- **R10-9**：至少 2 個 regime 同號，且合計 t 達標

**硬規則** **不要只依靠單一策略。** 若一個公式只在牛市有效，它的本質是
方向性多頭曝險，不是選股能力——這種結果必須標示為
「實質上是 beta，不是 alpha」。可行的處置是**多公式並存**：
不同 regime 用不同公式，或依 regime 動態調整曝險。
**但這屬於組合層決策，超出本專案範圍**（R19）——本專案只負責把
「這個公式在哪些 regime 有效」講清楚。

#### R16 樣本量、重抽樣與集中度

樣本太少的三種表現，逐一檢查：

| # | 檢查 | 做法 | 不通過的樣子 |
|---|---|---|---|
| Q1 | **統計效力** | 報 95% 信賴區間 | CI 寬度 > \|毛年化邊際\| → 結論不成立 |
| Q2 | **重抽樣** | **block bootstrap**，block 長度 = `ceil(horizon)`，≥ 1,000 次 | bootstrap 95% 分位跨過 0 |
| Q3 | **交易集中度** | 剔除最佳 5% 交易後重算 | 剔除後翻號（R10-10） |
| Q4 | **貢獻度分解** | 逐交易、逐標的、逐期間的報酬貢獻占比 | 單一標的或單一期間貢獻 > 30% |

**為什麼用 block bootstrap 而不是一般 bootstrap**：本專案的報酬序列有
自相關（見 R8）。一般 bootstrap 會打散自相關結構，**低估**變異數，
產生過度樂觀的信賴區間。block 長度必須至少等於持有期。

**若 Q1 就已經不通過**（CI 寬度超過效應），**不必**繼續做 Q2–Q4。
樣本量不足時，增加檢查只會得到更多噪音。

**硬規則** 見 S-32、S-33。Bootstrap 的重抽樣單位是**期間**不是**交易**；
用交易重抽會嚴重高估樣本數。

### F. 誠實性與流程

#### R17 誠實性與可稽核性

- 通過與不通過**同等重要**，都必須寫進 `history.md`
- 被淘汰的提案**全部保留**，附淘汰原因
- 任何量測錯誤必須記錄（寫進 `process.md`）
- **不得**因為預期好消息而調整任何步驟
- **不得**因為結果不符期待而改權重、改期間、改門檻後重跑並只報有利結果
- 磁碟上留著一份過期的失敗報告，比沒有報告更糟。程式碼改了就重跑產出
- **每一輪的 harness 必須有 prefix invariance 測試**（R7 的自我測試要求）
- 每一輪的**詳細結果必須寫進 `out/<round-id>/`**。
  只有回報文字、repo 內無 artifact 的條目，在 `history.md` 標為
  `[report]` 且**不可稽核**——不可稽核的結果**不得**用於修改主專案

#### R18 唯讀

本研究**唯讀**。不得：

- 建立或修改任何 execution ledger
- 寫入 `~/.tradingbuffett/`（含 safety / long_run，會影響 kill switch / HWM）
- 觸發任何券商 mutation
- 呼叫 LLM

所有 `TRADINGBUFFETT_*` 路徑變數必須導向 `research/data/`（`src/common.py`
的 `ISOLATED_ENV` 已在 import 時強制執行）。

#### R19 範圍膨脹

發現需要 backtest engine、部位 sizing、停損、最大回撤斷路器、動態曝險
調整、組合最佳化才能回答核心問題時，**停下來回報，不要自行擴充**。

**特別注意 R14 的邊界**：風險管理是主專案的事。本專案做風控不是為了
做得完整，是為了**揭露公式能不能被主專案的風控層安全使用**。


```
── 驗證期（2021–2025，只跑一次）──────────────────────────
```

不可稽核的結果**不得**用於修改主專案（R17）。

5. 不在同一份資料上做「挖掘 → 驗證 → 再挖掘」的迭代
6. 不在證據不足時修改主專案的選股邏輯
7. 不刪除失敗的輪次（見 §3.2）

### 8.2 **不做，因為那是主專案的事**（R14 的邊界）

這些是合理的風控要求，但把它們放進公式搜尋會產生**錯誤的安全感**——
一個沒有停損、沒有回撤斷路器的回測數字，不能因為「本專案有做嚴謹的
穩健性檢查」就被當成可部署策略。

| 不做 | 歸屬 | 為什麼不放這裡 |
|---|---|---|
| 部位 sizing、依波動率調整權重 | 主專案 | 會讓公式搜尋變成投資組合最佳化 |
| 停損、獲利了結 | 主專案 | 屬於執行層，與選股公式正交 |
| 最大單日虧損、最大回撤、最大槓桿斷路器 | 主專案 safety layer | 主專案已有 `~/.tradingbuffett/safety/` |
| 動態曝險調整、依 regime 切換策略 | 主專案 | 需要組合層決策，見 R15 末段 |
| 相關性約束下的部位上限 | 主專案 | 本專案只**揭露** 20 檔的相關性（R14-H2） |
| 真正的容量研究 | 主專案 | 需要實際 fill 資料；R13-L2 只是預警 |

**本專案的職責是讓主專案的風控層有東西可用**（R14-H1/H2/H3），
不是取代它。發現某條公式需要這些才能安全使用時，
**回報使用者決定**，不要自行擴充（R19）。
